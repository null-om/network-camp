How devices communicate inside a local network, and how VLANs divide it into separate logical segments.

Layer 2 device

What is a switch?

A switch connects devices inside a LAN. Instead of repeating traffic everywhere, it reads the destination MAC address of each Ethernet frame and forwards it where it needs to go.

HubSwitch
LayerLayer 1 · PhysicalLayer 2 · Data Link
ForwardsEvery signal out of every other portFrames toward the destination MAC address
AwarenessNone; it does not read addressesReads source and destination MAC addresses
TodayObsoleteThe standard LAN building block

Same cable, smarter device. A hub shouts every frame to everyone; a switch delivers it to the right port.

The basic process

How does a switch work?

1
Learn
Frame arrives: record its source MAC and the port it came in on.
2
Look up
Search the MAC address table for the frame’s destination MAC.
3
Forward
Entry found: send the frame out of that port only.
4
Flood
No entry (unknown unicast): send it out of all ports except the incoming one.
MAC address table · also called the CAM table
MAC addressPort
AA:AAP1
CC:CCP3

MAC addresses shortened for readability.

Learn from the source, forward by the destination. The switch builds its table automatically; nobody configures it. Entries expire if a device stays silent (5 minutes by default on Cisco).

ARP: Connecting IP to MAC

The problem. PC-A knows PC-B’s IP address, 192.168.1.20. But an Ethernet frame needs a destination MAC address, and the switch forwards using only that. ARP (Address Resolution Protocol) discovers the MAC address that belongs to a known IPv4 address on the local network.

ARP RequestARP Reply
Asks / says“Who has 192.168.1.20? Tell 192.168.1.10”“192.168.1.20 is at BB:BB”
Sent asBroadcast · FF:FF:FF:FF:FF:FFUnicast · straight to AA:AA
WhyThe sender does not know the MAC yet, so it asks everyone on the segmentThe owner now knows who asked, so no broadcast is needed
ARP

Resolves an IPv4 address to a MAC address.

The switch

Forwards frames using MAC addresses, not IP addresses.

Together

ARP itself makes no forwarding decision. It is just a message the switch carries like any other frame (a broadcast, so it floods).

PC-A wants to talk to 192.168.1.20

ARP step by step

1
Local destination
Same network as PC-A (192.168.1.0/24), so PC-A needs the target’s MAC.
2
Check ARP cache
192.168.1.20 → ? No entry yet.
3
ARP Request
Broadcast: Who has 192.168.1.20? Dst MAC FF:FF:FF:FF:FF:FF.
4
Switch floods
Out of all ports in the same broadcast domain except the incoming one. It learns AA:AA on P1. PC-C and PC-D ignore it.
5
ARP Reply
PC-B answers PC-A by unicast: 192.168.1.20 is at BB:BB.
6
Send the frame
PC-A caches 192.168.1.20 → BB:BB and sends Ethernet frames to Dst MAC BB:BB.

Three different passwords

Securing Switch Access

Console password · protects the physical console connection 
Switch(config)# line console 0
Switch(config-line)# password <CONSOLE_PASSWORD>
Switch(config-line)# login
Switch(config-line)# exit

login turns on password checking for the console line. Without it, the password is never asked.

Enable password · protects Privileged EXEC mode 
Switch(config)# enable password <ENABLE_PASSWORD>
Enable secret · the preferred way to protect Privileged EXEC 
Switch(config)# enable secret <ENABLE_SECRET>
ConfigurationPurpose
Console PasswordProtects console access
Enable PasswordProtects Privileged EXEC access
Enable SecretPreferred protection for Privileged EXEC access

Two different doors. The console password decides who can reach the CLI. The enable password or secret decides who can enter Privileged EXEC (enable).

Prefer the secret. enable secret takes precedence when both are set, and it is stored as a one-way hash. enable password is stored as plain text in the configuration.

Replace every <PLACEHOLDER> with your own strong password. Never reuse the examples.

Domains

Broadcast & collision domains

Collision domain

Devices whose transmissions can collide because they share the same medium. Hubs create one big shared domain. A switch gives every port its own, so frames no longer fight for the same wire.

Broadcast domain

All devices that receive a broadcast frame (destination FF:FF:FF:FF:FF:FF). A switch floods broadcasts out of every port, so all its ports stay in one broadcast domain, and so does every device in the same VLAN.

Collision domainsBroadcast domains
Hub, 4 PCs11
Switch, 4 PCs4 (one per port)1
Switch + 3 VLANsone per port3 (one per VLAN)

On modern full-duplex switch links collisions no longer happen in practice, but the term still describes how a switch isolates each port.

Logical segmentation

What are VLANs?

A VLAN (Virtual LAN) splits one physical switch into several logical networks. Each VLAN is identified by a VLAN ID (1–4094) and acts as its own broadcast domain.

01Smaller broadcast domainsA broadcast, including ARP, only reaches devices in its own VLAN. 02SeparationDepartments are isolated at Layer 2, even on the same hardware. 03FlexibilityGroup devices by role, not by where the cable happens to land.

VLANs are logical boundaries created by configuration, not by extra cables or extra switches.

All six PCs plug into the same physical switch, yet they belong to three separate logical networks. Only the HR devices receive HR’s broadcasts.

Two port types

Access & trunk ports

Access portTrunk port
VLANsBelongs to one VLANCarries many VLANs
ConnectsEnd devices: PCs, printersSwitch to switch
FramesNormally untaggedTagged with IEEE 802.1Q

The tag is the VLAN’s name badge. Without it, the switch on the far side could not tell which VLAN a frame belongs to.

Optional note: one native VLAN can cross a trunk untagged (VLAN 1 by default on Cisco). Both ends must agree on it.

What you should observe

Expected results

TestResultWhy
PC1 → PC4 · HR ↔ HR across the trunkWorksSame VLAN. The trunk carries VLAN 10 frames, tagged, between the switches.
PC2 → PC5 · IT ↔ IT
PC3 → PC6 · Finance ↔ Finance		WorksSame reason, different VLAN. One trunk carries all three.
PC1 → PC2 · HR → IT, same switchFailsDifferent VLANs are separate broadcast domains and separate subnets. Layer 2 switching alone will not connect them.
PC1 → PC5 · HR → IT, across the trunkFailsThe trunk keeps VLANs separate; it does not merge them.
Look closer
  • The first ping often times out while ARP resolves, then succeeds.
  • Run arp -a on PC1: PC4’s MAC appears. PC2’s never does.
Break it on purpose
  • Move PC4’s port to VLAN 20: PC1 ↔ PC4 stops working.
  • Make Gi0/1 an access port: nothing crosses between the switches.

Communication between VLANs needs a Layer 3 device. That is outside the scope of this session.

Recap

Key takeaways

01 · Switching

A switch learns source MAC addresses and builds its MAC address table.

02 · Forwarding

Known destination: one port. Unknown unicast or broadcast: flood within the VLAN.

03 · Domains

Each switch port is its own collision domain. A VLAN is one broadcast domain.

04 · ARP

ARP resolves an IPv4 address to a MAC address; its request is a broadcast.

05 · VLANs

VLANs split one physical switch into separate logical networks.

06 · Port types

Access ports serve one VLAN; trunk ports carry many using 802.1Q tags.
