Introduction to
Networking

Networks, devices, protocols, and the models that explain how data moves.

The question

How does data travel from one device to another?

Keep this question in mind. By the end of the session, you will be able to follow the journey step by step.

Foundations

What is a network?

A network is a group of connected devices that exchange data by following agreed rules.

  • Devices connect through wired or wireless links.
  • They exchange information and share resources and services.
  • Communication needs both a connection and compatible protocols.

A network does not have to be connected to the internet. A few computers in a lab form a network on their own.

Purpose

Why do we need networks?

Communicate

Messages, calls, and video between people and devices.

Share

Laptops sharing files, or a whole office using one printer.

Use services

A student opening the university portal or a shared application.

Reach far away

Connecting to remote systems and the internet.

Classification

Networks by scope

PAN

Personal Area Network. Around one person, like a phone and Bluetooth earbuds.

LAN

Local Area Network. One site: a home, office, lab, or university building.

MAN

Metropolitan Area Network. Spans a city-scale area.

WAN

Wide Area Network. Connects sites across regions or countries.

These are geographic categories, not strict rules. Speed and ownership do not define them. The internet connects networks around the world.

Arrangement

What is network topology?

Topology is the arrangement of devices and the connections between them.

It affects how devices connect, what happens when something fails, how easily the network grows, and how much it costs to build and manage.

Physical topology is how cables and devices are laid out. Logical topology is how data flows. Today we focus on the shapes.

Common shapes

Bus, star, and ring

Bus

  • Devices share one backbone, so cabling is minimal.
  • A backbone failure can disrupt everyone.
  • Mostly a historical or conceptual example today.

Star

  • Every device connects to a central device.
  • Easy to manage and expand.
  • One broken link usually affects only that device, but if the center fails, the network is disrupted.

Ring

  • Devices are arranged in a ring, physically or logically.
  • Traffic follows the ring's forwarding arrangement.
  • Failure behavior depends on the technology and on whether redundancy exists.
Larger designs

Mesh and hierarchical

Mesh

  • Devices have multiple interconnections.
  • Extra paths can improve resilience when forwarding or routing can use them.
  • More links mean higher cost and complexity.

Extended star (hierarchical)

  • Several stars joined in a structured hierarchy.
  • Easier to organize and grow large networks.
  • A common model for offices and campuses.

These ideas overlap: a hierarchy is made of star sections. Not every topology is equally common today. The goal is familiarity, not memorization.

The building blocks

Network components

End devices

Where data starts and ends

Laptops, desktops, smartphones, printers, and servers. They send, receive, and use network services.

Network devices

What moves the data

  • Switch: connects devices inside a local network.
  • Router: connects different networks.
  • Access point: lets wireless devices join the wired network.
Transmission media

What carries the signal

  • Copper Ethernet cabling
  • Optical fiber
  • Wireless radio signals
Foundational distinction

Switch vs. router

Layer 2 · Frames

Switch

  • Connects devices within a local network.
  • Learns source MAC addresses and uses its MAC address table to forward Ethernet frames.
  • In its basic Layer 2 role, it does not route between separate IP networks.
Layer 3 · Packets

Router

  • Connects different IP networks.
  • Uses IP addresses and its routing information to forward packets toward their destinations.

A switch forwards frames within a Layer 2 network; a router forwards packets between IP networks.

The rules

Communication and protocols

Every exchange has a sender, a receiver, and a medium. A protocol is a set of rules for how devices format, exchange, interpret, and handle information.

These protocols do different jobs. They work together, they do not compete.

Two kinds of address

MAC address vs. IP address

Layer 2 · Local link

MAC address

  • Identifies an interface in local network communication.
  • Ethernet frames use it for delivery on the local link.
  • Can be changed or locally administered, so it is not always permanent.
Layer 3 · Across networks

IP address

  • A logical address that helps deliver packets across IP networks.
  • IPv4 uses 32 bits; IPv6 uses 128 bits.
  • Set manually or automatically, for example by DHCP.

Both addresses can exist on the same interface. The MAC address handles the next hop; the IP address describes the final destination. Subnetting comes in Session 02.

Making it manageable

Why do we need network models?

Communication involves many jobs. A model splits them into layers we can understand one at a time.

  • Break a complicated process into understandable parts.
  • Give everyone a shared vocabulary.
  • Help isolate problems when troubleshooting.
  • Show how different protocols fit together.

The OSI model is a conceptual framework. It is not a device, and it does not describe every real implementation perfectly.

Reference model

The OSI model

Seven layers, from the application at the top to the signal at the bottom. A memory aid, top to bottom: All People Seem To Need Data Processing.

Real protocols do not always fit one layer neatly. For example, TLS does not belong exclusively to Layer 6.

Putting it together

Following data through the layers

Encapsulation: each layer wraps the data with the information it needs for its part of the journey.

Along the path, a switch reads the local-link frame. A router looks at the IP packet and forwards it toward another network.

Recap

Key takeaways

Networks connect devices so they can exchange data and share resources.

Topology describes how devices and links are arranged.

End devices, switches, routers, and media each have a different role.

Protocols define how communication works.

MAC and IP addresses serve different purposes.

OSI and TCP/IP help us understand communication layer by layer.
